Core Concepts KEY CONCEPTS

Sequences

A Sequence is an ordered list of spell casts or macro commands that execute one-per-keypress.

Anatomy of a Sequence

Name: "Fire_Mage_ST"
Icon: 🔥
Steps:
  1) Pyroblast
  2) Flame Blast
  3) Fireball
Step Function: Sequential
Keybind: V (per-spec)
Reset Condition: No Target
Context Versions: Default, Raid, Dungeon

Step Functions KEY CONCEPT

Determines how the sequence advances through steps when you press the key:

Sequential

Execute steps in order: 1 → 2 → 3 → 1 → ...

Best for: Fixed rotations, openers, cast sequences.

Priority

Execute the highest-priority available step each press.

Best for: Dynamic rotations, conditions, smart casting.

Random

Pick a random step each press (weights configurable).

Best for: Variation, PvP mind games, proc weighting.

Reset Conditions KEY CONCEPT

Define when the sequence resets to step 1. Choose one or more:

Condition Triggers When
COMBAT_LEAVE You leave combat (PLAYER_REGEN_ENABLED)
TARGET_CHANGE Your target changes or dies
SPELL_CAST_SUCCESS Any spell is cast (useful for Priority mode)
TIMER N seconds pass without a keypress
SPEC_CHANGE You switch specialization
EQUIPMENT_CHANGE Your gear set changes

Multi-Version Sequences SHIPPED

Create different step lists for the same sequence (v1, v2, v3, etc.). Use cases:

  • Raid vs Dungeon: Different priorities based on encounter
  • AoE vs Single Target: Different step counts or casts
  • Talent variants: Adjust rotation for talent builds
  • Gear tiers: Optimize for item level

Context Auto-Switching SHIPPED

Automatically switch between sequence versions based on zone/encounter/PvP status:

Example: You have Fire_Mage_ST with 3 versions:

  • v1 Default: Basic 5-step opener
  • v2 Mythic+: Optimized for dungeon DPS, shorter CD waits
  • v3 Raid Bosses: Extended rotation with procs

When you enter a Mythic+ dungeon, GRIP-EMS automatically switches to v2. When you enter a raid, v3 activates. Seamless.

Variables KEY CONCEPT

Use ~varname~ placeholders in your steps. They substitute at compile time:

/cast ~target~ [noharm] Dispel Magic; /cast [harm] Corruption

Variable types:

  • User Variable: Static text you set once
  • Function Variable: Evaluated every cast (e.g., UnitName("target"))
  • Event-Bound Variable: Updates when an event fires

Keybinds KEY CONCEPT

GRIP-EMS uses WoW's SetOverrideBindingClickA protected API that temporarily overrides your keybinds without modifying your saved bindings. It resets on zone changes and logout. system, which means:

  • Per-spec keybinds (different key for each specialization)
  • Temporary (never saved to your bindings file)
  • Auto-suspend in protected frames (boss encounters, PvP arenas)
  • Instant activation (no reload UI needed)

Understanding the Editor

Working Copy Pattern

When you edit a sequence, you're editing a working copy. Changes aren't committed until you click Save. This prevents accidental data loss and lets you discard changes safely.

Dirty State

The interface shows unsaved changes with a visual indicator (exclamation mark or color change). The Save/Discard buttons become prominent when there are changes.

Spell Autocomplete

Type a spell name and GRIP-EMS suggests matches from your spellbook. Works for class spells, racials, and even shared abilities.

Version Bar

Above the tabs, you'll see version buttons (v1, v2, etc.). Click to switch between multi-version edits. Right-click to create/duplicate/delete versions.

Import & Migration

Why Import?

GRIP-EMS fully supports importing sequences from other addons. Whether you're switching from a different sequencer or combining collections, importing makes the transition seamless.

Two Import Methods

Method 1: In-Game

Open your old addon and trigger a migration check. GRIP-EMS detects installed addons and offers bulk import.

  • Automatic detection
  • One-click import all
  • Name conflict resolution
  • Fastest method

Method 2: Clipboard

Export from the old addon, copy to clipboard, paste in GRIP-EMS import window.

  • Single sequence at a time
  • Works cross-account
  • Selective import
  • Manual control

Advanced Topics

WoW Macro Conditionals Cheat Sheet

Use these in your steps for conditional casting:

Targeting

/cast [harm] Corruption; [help] Heal

[harm] = hostile target
[help] = friendly target
[noharm] = non-hostile

Modifiers

/cast [mod:shift] Spell1; Spell2

[mod:shift] = Shift held
[mod:ctrl] = Ctrl held
[mod:alt] = Alt held

Game State

/cast [combat] Spell1; Spell2

[combat] = in combat
[nocombat] = out of combat
[mounted] = on mount

Position

/cast [@mouseover] Heal

[@mouseover] = under cursor
[@player] = cast on self
[@focus] = focus target

255-Character Limit Tips

Each step in WoW macros has a 255-character limit. Here are optimization strategies:

Use semicolons to chain conditions on one line:

LONG:  /cast [combat,harm] Corruption
       /cast [nocombat] PW:Shield

SHORT: /cast [combat,harm] Corruption; [nocombat] PW:Shield

Remove unnecessary spaces and combine conditions with commas.

If a step exceeds 255 chars, split it across steps:

Step 1: /cast [harm] Corruption; /cast [help] PW:Mend
Step 2: /cast [mod:shift] Death Coil; [nocombat] Dark Mend

With Sequential mode, they execute in order. With Priority mode, highest-priority available cast wins.

Priority Step Function Deep Dive

Priority mode evaluates all steps and casts the highest-priority available spell.

How It Works

Each step is evaluated in order (1 → 2 → 3). The first step whose conditions are met is cast. If no conditions are met, nothing happens.

Step 1: /cast [combat,harm] Corruption
Step 2: /cast [combat,noharm] Auto Attack
Step 3: /cast [nocombat] Buff

Press key in combat with hostile target → Corruption cast
Press key in combat with friendly/no target → Auto Attack cast
Press key out of combat → Buff cast

Variable Functions (Lua Examples)

Function variables execute Lua and return a string to substitute:

Get Target Name

return UnitName("target") or "player"

Returns target name or "player" if none.

Check Target Power

return UnitPower("target") > 0 and "target" or "player"

Uses target if it has power, else self.

Class-Based String

local class = select(2, UnitClass("player"))
return class == "WARRIOR" and "Whirlwind" or "Spin"

Returns different strings per class.

Random Group

return ({ "spell1", "spell2", "spell3" })[math.random(3)]

Returns random spell from list.

Debug & Troubleshooting

Issue Solution
"Spell not found" Check spell name spelling. Use exact in-game name or macro command.
Keybind doesn't work Check if you're in a protected frame (boss fight, arena). Try a different key.
Steps don't advance Make sure Step Function is set correctly. In Priority mode, check conditions.
Variable not substituting Ensure ~varname~ matches exactly (case-sensitive). Check function returns a string.
Import fails Try method 2 (clipboard). Paste only the export string, not extra text.

The OOC Queue Explained

GRIP-EMS defers certain protected API calls until out of combat via the OOC Queue mechanism.

What's Protected?

WoW prevents addons from executing certain API calls during combat (e.g., SetOverrideBindingClick, macro creation). GRIP-EMS queues these and processes them when you leave combat.

Why?

Safety. Protected APIs prevent addons from making unfair combat advantages or breaking macros during encounters.

SetOverrideBindingClick Explained

GRIP-EMS uses SetOverrideBindingClick to bind your keys. Here's the technical breakdown:

What It Does

Temporarily overrides your keyboard inputs to trigger a click on a hidden frame. When you press V, WoW pretends you clicked on the GRIP-EMS button for that sequence.

Advantages

  • Doesn't modify your saved bindings
  • Per-spec (can differ per specialization)
  • Auto-suspends in protected frames
  • Instant (no UI reload needed)

Limitations

  • Temporary (resets on logout/zone change)
  • Only one binding per key across all addons
  • Can't override reserved keys (Print Screen, etc.)
