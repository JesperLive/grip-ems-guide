How GRIP-EMS Works (30-Second Version)

1. You create a sequenceAn ordered list of macro steps. Each step contains WoW macro text like "/cast Kill Command" or "/cast Barbed Shot". -- a list of spells in the order you want them cast.

2. You bind that sequence to a keybindA keyboard key or mouse button. GRIP-EMS uses SetOverrideBindingClick, which is per-spec and temporary -- it never modifies your saved WoW keybindings..

3. Every time you press that key, GRIP-EMS fires the next spell in the list and advances to the next step.

4. The sequence loops, resets on combat end, or resets based on your configured conditions.

That's it. One key, full rotation.

Core Concepts

What is a Sequence?

A sequence is an ordered list of macro stepsEach step is a standard WoW macro -- the same text you'd type in /macro. Supports /cast, /use, /castsequence, conditionals like [mod:shift], and more.. When you press your keybind, GRIP-EMS executes the current step and advances to the next one.

Each sequence has:

PropertyDescription
NameUnique identifier for the sequence
StepsThe list of macro text strings (one per step)
Step FunctionHow GRIP-EMS decides which step to execute next
IconAuto-detected from the first step's spell, or manually chosen
Reset ConditionsWhen the sequence resets back to step 1
KeyPress / KeyReleaseMacro text that runs before/after every step

Step Functions

The step function determines how GRIP-EMS picks the next step to execute.

Sequential

Steps execute in order: 1, 2, 3, ... N, then loop back to 1. Best for rotations with a fixed priority order.

Step 1: /cast Kill Command Step 2: /cast Barbed Shot Step 3: /cast Cobra Shot Step 4: /cast Cobra Shot --> loops to Step 1

Priority

All steps are compiled into a single macro using /castsequence resetPriority mode compiles all steps into one macrotext block. WoW tries each /cast line top-to-bottom on every keypress, so highest-priority spells go first.. WoW tries each line in order -- the first castable spell fires. Best for proc-based rotations where you want the highest-priority ability that's ready.

Compiled macro: /cast Kill Command /cast Barbed Shot /cast Cobra Shot --> WoW tries Kill Command first, falls through to Barbed Shot, then Cobra Shot

Random

Each keypress picks a random step. Useful for flavor abilities or when order doesn't matter.

Reset Conditions

Sequences reset to step 1 when any of these conditions are met:

ConditionWhen It TriggersDefault
CombatYou leave combat (PLAYER_REGEN_ENABLED)On
TargetYou change targets (PLAYER_TARGET_CHANGED)Off
TimerNo keypress for N seconds (idle timeout)Off
GearYou equip or unequip an itemOff

Multi-Version Sequences

Each sequence can have multiple versions -- for example, a single-target version and an AoE version. Use the version bar at the top of the editor to add, duplicate, delete, or switch between versions.

One version is marked as the default (shown with a * indicator). The default version runs when no context override matches.

Context Auto-Switching

GRIP-EMS detects what content you're doing (raids, dungeons, M+, PvP, etc.) and automatically picks the right version of each sequence.

Open the Context tab in the editor to assign versions to contexts. Contexts are organized in collapsible groups: Raids, Dungeons, PvP, and Other. Each context has a dropdown to pick which version runs when you're in that content.

If no specific context match exists, GRIP-EMS follows a fallback chain. For example, if you set a version for "Raid" but not "Raid Heroic," heroic raids will use the general Raid version. The final fallback is always the default version.

Context Groups:

  • Raids: Normal, Heroic, Mythic
  • Dungeons: Normal, Heroic, Mythic+
  • PvP: Arena, Battleground, Rated BG
  • Other: Scenario, Timewalking, Delves, Solo, Default

Variables

Variables let you define reusable values that get substituted into your macro steps. Write ~varname~ in any step and GRIP-EMS replaces it at compile time.

Variable "trinket1" = "Cantrip of Cooling" Step: /use ~trinket1~ Compiles to: /use Cantrip of Cooling

Variables can be simple strings or Lua functions that evaluate dynamically. They're account-wide -- shared across all characters.

How Keybinds Work

GRIP-EMS uses SetOverrideBindingClickA WoW API that creates temporary keybinds. They override your normal binds while active, but are never saved to your keybinding profile. They disappear on /reload unless the addon re-applies them. to bind keys to sequences. This means:

Per-spec: Each spec has its own keybind set. Switch specs and your DPS/healer/tank binds swap automatically.

Temporary: Binds are applied on login and cleared on /reload. They never touch your saved WoW keybinds.

OOC-safe: Keybind changes are deferred to out-of-combat if you're in combat (WoW requires this for protected API calls).

Auto-suspend: All keybinds suspend during vehicles, skyriding, and pet battles, then restore automatically.

Editor Guide

The GRIP-EMS editor has 5 tabs for managing every aspect of your sequences.

Steps Tab

The main editing view. Each step is an editable text field containing WoW macro text.

ActionHow
Add a stepClick the + button below the step list
Remove a stepClick the X on the right side of the step
Move stepsUse the arrow buttons to reorder
Spell autocompleteType a spell name and press Tab -- a dropdown shows matching spells from your spellbook
Variable autocompleteType ~ and press Tab to see available variables
Character counterEach step shows its character count (max 255 per WoW macro limit)

Working copy pattern: Edits happen on a copy of your steps. Nothing is saved to the engine until you click Save. This means you can experiment freely -- click Discard to revert.

Keybind Tab

Assign a key to this sequence for the current spec.

ActionHow
Set keybindClick the capture box, then press the desired key/combo
Clear keybindClick the clear button next to the binding
Per-spec overviewShows which key is bound for each of your specs

Modifier keysShift is the most reliable modifier for WoW macros. Ctrl is medium reliability. Alt is unreliable because WoW uses it for self-cast by default. Avoid Alt combos unless you've disabled self-cast. work too -- Shift+1, Ctrl+F, etc.

Macros Tab

Manage the WoW macro stubs that give you drag-to-action-bar icons.

How it works: GRIP-EMS creates a real /macro for each sequence so you can drag it to your action bar. The macro is visual only -- execution always goes through the keybind system, not the macro button.

The Macros tab shows: macro slot usage (per-character and account-wide), stub list, and an orphan cleanup button to delete stubs for sequences that no longer exist.

Variables Tab

View and edit account-wide variables. Unlike other tabs, this shows the same content regardless of which sequence is selected.

ActionHow
Create variableType a name and function body, click Save
Test variableClick Test to evaluate the function and see the result
Event bindingComma-separated WoW events that trigger re-evaluation (e.g., PLAYER_EQUIPMENT_CHANGED)
Delete variableSelect it and click Delete

Raw Tab

Shows the full Lua table representation of your sequence data. Read-only by default.

Click Edit to enable editing -- you can modify the raw Lua directly. Click Apply to validate (pcall + loadstring) and apply changes. The validator checks for required fields (name, steps, stepFunction) before accepting.

Power User This is for advanced users who want to edit sequence internals directly.

GSE Migration

Already using GSE? Transfer everything to GRIP-EMS in minutes.

Method 1: In-Game Migration (Recommended)

This transfers all your GSE sequences and variables in one click.

  1. Install GRIP-EMS (keep GSE active or disabled -- both work)
  2. Open GRIP-EMS: type /gems in chat
  3. Click the Migrate from GSE button in the sequence list panel
  4. Confirm in the popup dialog
  5. Read the migration report in chat -- it shows what transferred, what was skipped, and any warnings
  6. Test your sequences. When satisfied, disable GSE in your addon list

Method 2: Clipboard Import

For individual sequences, or if GSE isn't installed.

  1. In GSE, select a sequence and click Export
  2. Copy the export string (Ctrl+C)
  3. In GRIP-EMS, type /gems import
  4. Paste into the window and click Import

Migration Report

After migration, GRIP-EMS prints a structured report to chat showing:

  • Total sequences and variables migrated
  • Per-sequence details (name, step count, step function)
  • Limitation counts (context overrides imported, pauses skipped, embeds skipped, steps truncated)
  • Per-sequence warnings (if any)
  • Post-migration guidance tips

The full report is also captured in the Debug Window (/gems debugwindow) for later review.

Advanced Topics

WoW Macro Conditionals

Each step supports full WoW macro syntax including conditionals. Common patterns:

/cast [mod:shift] Multi-Shot; Kill Command /cast [target=focus,exists] Misdirection /cast [combat] Bestial Wrath /use [combat] 13 /cancelaura Aspect of the Turtle
ConditionalMeaning
[mod:shift]Only when Shift is held
[combat]Only when in combat
[nocombat]Only when out of combat
[target=focus,exists]Only if focus target exists
[noharm][dead]If target is friendly or dead
[@player]Target self
[@cursor]Place AoE at cursor (no green circle)

The 255-Character Limit

WoW enforces a 255-character limit per macro text block. This applies to each step individually. If a step exceeds 255 characters (including KeyPress/KeyRelease prepend/append), the step is truncated with a warning.

Tips to stay under the limit:

  • Use ~variables~ for long spell names or shared blocks (substitution happens before the limit check)
  • Keep conditionals concise -- [mod:shift] not [modifier:shift]
  • Split complex logic across multiple steps
  • Use /use 13 instead of /use Trinket Name Here for trinket slots

Priority Step Function Deep Dive

Priority mode compiles all steps into a single macro block. This is powerful but has trade-offs:

Pros: The "right" spell always fires. No wasted keypresses on cooldown abilities.

Cons: All steps must fit in 255 characters combined. The compiled preview in the editor shows you the final macrotext and character count.

Best for: Proc-based rotations (e.g., BM Hunter where Kill Command/Barbed Shot have irregular availability).

Variable Functions

Variables can be Lua functions that return dynamic values:

-- Simple string variable: "Cantrip of Cooling" -- Dynamic function (evaluates at compile time): (function() if UnitLevel("player") >= 80 then return "Flask of Alchemical Chaos" else return "Phial of Tepid Versatility" end end)()

Bind variables to WoW events so they re-evaluate automatically. For example, bind a trinket variable to PLAYER_EQUIPMENT_CHANGED so it updates when you swap gear.
